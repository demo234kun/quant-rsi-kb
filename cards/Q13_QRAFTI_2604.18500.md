## 一句话结论

> 一个"模拟量化研究团队"的多 agent 框架：用 **MCP 服务器**把面板数据访问、因子构造、自定义编码操作暴露为可调用工具，支持复现既有因子、检验新信号、生成带叙述与计算痕迹的标准化研究报告；关键经验：在多步实证任务上，**链式工具调用 + 反思式规划（reflection-based planning）可能比单纯动态代码生成更优、更可解释**。

## 问题背景

- 权益因子研究依赖大型金融面板数据集，重复性劳动大、可复现性差。
- 单 agent 动态代码生成在多步实证任务上易失控且难以解释。
- 需要一个能"模拟研究团队分工"的框架：工具、数据、标准化报告一体化。

## 方法

1. **多 Agent 框架**：模拟量化研究团队分工（数据、因子、实证、报告等角色）。
2. **MCP 服务器**：把数据访问、因子构造、自定义编码操作封装成可调用工具（工具即服务）。
3. **任务类型**：复现既有因子、构建与检验新信号、生成标准化研究报告。
4. **链式工具调用 + 反思式规划**：多步任务用链式调用累积中间结果，并用反思规划替代一次性代码生成。
5. **产物**：研究报告 + 叙事分析 + computational traces（计算痕迹，保证可复现）。

## 关键结果

| 实验 | 结果 |
|---|---|
| 多步实证任务 | 链式工具调用 + 反思式规划可能优于纯动态代码生成 |
| 可解释性 | 反思式规划提供比代码生成更好的可解释性 |
| 报告产物 | 标准化研究输出 + 计算痕迹，可复现可审计 |

## 与 RSI 知识库的关系

- **反思阶段 = 自批判**：QRAFTI 的"反思+自我批评"是 RSI 的轻量自改进组件（热点文件方向4 明确列它含反思/自我批评阶段）。
- 工具化（MCP 服务）让 agent 的改进对象从"代码"扩展到"工具组合"，与 SICA 类"改进自身工具集"思想一致。
- 计算痕迹（traces）保证"每个结论都能追溯到执行路径"——金融 RSI 可审计性的基础。

## 解读与批判

- ✅ "链式调用 + 反思 > 动态代码生成"是一个可操作的经验结论，直接指导 agentic 金融研究系统设计。
- ✅ MCP 服务化工具接口，工程上可复用、可扩展。
- ⚠️ 摘要级结论为"可能优于"，未见具体数值对比强度（需读正文）。
- ⚠️ 面向"复现/检验"的研究工具定位，未覆盖长周期自进化记忆（与 [Q23 EVOQUANT] 的蒸馏机制不同）。
